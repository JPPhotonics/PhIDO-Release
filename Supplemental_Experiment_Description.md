Supplemental Document: LLM Performance Evaluation for PDK Component Retrieval

This experiment was designed to systematically evaluate how Large Language Model (LLM) retrieval performance scales with Process Design Kit (PDK) size in photonic component libraries. The study investigates the relationship between search space complexity and retrieval accuracy, providing insights into the scalability of LLM-based component retrieval systems for photonic design automation.

The experiment utilized the GDSFactory photonic component library as the dataset, containing 262 total components including waveguides, couplers, resonators, gratings, electrical pads, and test structures. Each component was enhanced with comprehensive descriptions including docstrings, function signatures, and inferred functionality to provide the LLM with rich contextual information. Component descriptions were formatted to include parameter information, detailed docstrings, and inferred port configurations, creating a realistic representation of how components would be described in actual PDK documentation.

Three PDK size configurations were established to test scaling behavior. The small PDK consisted of 50 components randomly sampled from the first 50 components in the library, representing a baseline with minimal search complexity. The medium PDK contained 50 components randomly sampled from the first half of the library (131 components), providing an intermediate complexity level. The large PDK included 50 components randomly sampled from the entire library of 262 components, representing maximum search complexity. This design allows for direct comparison of retrieval performance across different search space sizes while maintaining consistent component diversity within each PDK.

A critical aspect of the experimental design was the query generation strategy. Rather than using manually crafted queries that might introduce bias, the experiment employed LLM-generated natural language queries for each component. The LLM was prompted to create functional, conversational search queries based on component names and descriptions, ensuring that queries focused on component purpose rather than exact name matching. This approach generates realistic search scenarios that designers would actually use when looking for components, such as "Find a component for straight optical waveguides with thermal control" for a straight_heater component.

The evaluation methodology incorporated multiple performance metrics to provide comprehensive assessment. Retrieval accuracy was measured using pass@1 (correct component retrieved as first choice) and pass@3 (correct component retrieved within top 3 choices) metrics. Additional metrics included average ranking of correct components and error rates for failed retrievals. Token efficiency was tracked through total token consumption per PDK size and average tokens per query, providing insights into computational cost scaling.

Two LLM models were compared to assess performance differences: Google's Gemini 2.5 Pro and OpenAI's o1 model. Both models were configured with deterministic settings (temperature 0.1) and appropriate token limits. The system prompt was carefully engineered to guide the LLM to focus on functional matching rather than exact name matching, emphasizing the importance of port configurations and component functionality in retrieval decisions.

The experimental procedure followed a systematic approach. First, all GDSFactory components were loaded and enhanced with detailed descriptions including docstrings, function signatures, and inferred properties. PDKs of different sizes were then created through random sampling from the appropriate subsets of the component library. For each PDK, LLM-generated queries were created for all components, ensuring that each component had a corresponding natural language search query. The retrieval testing phase involved presenting each query to the LLM along with the complete set of component descriptions for the corresponding PDK, measuring both retrieval accuracy and token consumption.

The system prompt was designed to constrain the LLM to only consider components within the provided JSON context, ensuring that retrieval performance reflects the actual search space limitations rather than the LLM's general knowledge. The prompt emphasized the importance of matching port configurations and component functionality, providing clear instructions for returning component IDs in JSON list format. This approach ensures that the experiment measures genuine retrieval performance within constrained search spaces rather than general knowledge recall.

Token usage tracking was implemented comprehensively to measure computational efficiency across different PDK sizes. Each API call returned detailed token consumption information including prompt tokens, completion tokens, and total tokens. This data was aggregated per PDK size to calculate average token consumption and identify scaling patterns. The token efficiency analysis provides crucial insights for practical deployment considerations, as higher token usage directly translates to increased operational costs in real-world applications.

The experimental design addresses several potential confounding factors through careful methodology. Component sampling was randomized to ensure representative selection across different component types. Query generation was automated to eliminate human bias in search query formulation. The use of functional rather than name-based queries ensures that the experiment tests genuine semantic understanding rather than simple pattern matching. The systematic variation of search space size while maintaining consistent component diversity allows for clear attribution of performance changes to search complexity rather than component type differences.

Results from this experiment provide valuable insights into the scalability limitations of LLM-based component retrieval systems. The methodology enables direct comparison of retrieval performance across different PDK sizes, identification of optimal PDK sizes for maintaining high accuracy, and assessment of computational cost scaling. The comprehensive token tracking allows for cost-benefit analysis of different PDK configurations, informing practical deployment decisions for photonic design automation tools.

The experimental framework is designed to be reproducible and extensible, enabling future research into LLM-based design automation tools. The methodology can be adapted to other component libraries and extended to investigate additional factors such as query complexity, component description quality, and prompt engineering strategies. The systematic approach provides a foundation for understanding the fundamental limitations and opportunities of LLM-based component retrieval in photonic design automation.
